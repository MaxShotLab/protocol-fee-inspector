# Fee Income Methodology

This document describes how Protocol Fee Inspector calculates Maxshot fee income for Morpho and native vaults.

## Morpho vaults

Maxshot Morpho V2 vaults charge no fee and allocate their assets to corresponding Morpho V1 vaults. Protocol fee income is therefore generated by the V1 vaults, which charge 5% of accrued interest.

### Fee minting

When a V1 vault accrues interest:

```text
interest = max(totalAssets - lastTotalAssets, 0)

feeAssets = interest * 5%

feeShares = feeAssets * totalSupply
            / (totalAssets - feeAssets)
```

The vault mints `feeShares` to Maxshot's configured fee recipient.

### Dashboard valuation

The dashboard values every fee-share mint using the nearest available daily USD share price:

```text
accruedFeeUSD = feeShares * sharePriceUSD
```

The current value of fee shares that have not been redeemed is:

```text
unredeemedFeeUSD = outstandingFeeShares * currentSharePriceUSD
```

Underlying assets received when fee-attributed shares are redeemed are counted as redeemed fee income.

```text
currentFeeIncome = redeemedFeeUSD
                   + unredeemedFeeUSD
                   + pendingUnmintedFeeUSD
```

### Pending unminted fees

Interest can accumulate between the latest fee mint and the current block. For the current snapshot only, the dashboard estimates the corresponding unminted fee:

```text
pendingInterest = max(currentTotalAssets - lastTotalAssets, 0)

pendingFeeAssets = pendingInterest * 5%

pendingFeeShares = pendingFeeAssets * totalSupply
                   / (currentTotalAssets - pendingFeeAssets)
```

Historical as-of calculations do not include this estimate. They contain only fee shares actually minted by the selected date.

### Redemption attribution

If the fee-recipient wallet contains both principal shares and fee shares, their provenance cannot be distinguished onchain after commingling. The inspector applies fee-first attribution: withdrawals consume fee-attributed shares first. Affected routes are marked **Review**.

## Native vaults

Each native vault aggregates assets deployed across several chains. Its ledger on Base periodically finalizes an epoch containing total assets and total effective shares.

### Epoch yield

Conceptually, the ledger compares the new exchange rate with the previous finalized exchange rate:

```text
previousRate = previousTotalAssets / previousTotalShares

expectedAssetsAtPreviousRate = newTotalShares * previousRate

epochYield = max(newTotalAssets - expectedAssetsAtPreviousRate, 0)
```

Using the exchange rate prevents deposits, withdrawals and changes in share supply from being treated as investment yield.

### Protocol fee

The native-vault protocol fee is 5% of positive finalized epoch yield:

```text
feeAssets = epochYield * 5%
```

The ledger records the result in:

```text
EpochYieldProcessed(
    feeChainId,
    interestAccumulated,
    fees
)
```

It also converts fee assets into vault shares for the fee recipient on the configured fee chain:

- Native USDC fee shares mint on Base.
- Native USDT fee shares mint on Arbitrum.

### Dashboard calculation

The `fees` field already contains the finalized fee amount. The inspector therefore reads it directly instead of reconstructing it:

```text
feeIncomeForEpoch = event.fees / 10^assetDecimals

cumulativeFeeIncome = sum(feeIncomeForEpoch)
```

USDC and USDT use six decimals and are valued at approximately one USD per token.

Only finalized epochs are counted. The inspector does not currently estimate native-vault fees accumulated after the latest finalized epoch.
